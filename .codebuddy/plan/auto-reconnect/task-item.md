# 实施计划：仿付费版 ShareMouse 连接保活与自动重连

- [ ] 1. 重构 kvm-agent 连接管理器，移除主控端/被控端角色
   - 删除 `connection/manager.rs` 中的 `ConnectionRole::Controller` / `ConnectionRole::Controlled` 枚举
   - 将连接状态简化为 `Connected` / `Disconnected` / `Reconnecting` 三种
   - 移除 `main.rs` 中的角色切换逻辑，统一为"连接/断开"操作入口
   - 移除 `hotkey.rs` 中的"切换主控/被控角色"快捷键绑定
   - _需求：1.1、1.3、1.4、1.5、1.6_

- [ ] 2. 重构 transport.rs，统一为对等连接模型
   - 合并"主控端连接"和"被控端监听"两套逻辑为统一的连接处理函数
   - 发起方调用 `TcpStream::connect`，接受方调用 `TcpListener::accept`，连接建立后两端逻辑完全对称
   - 移除原有混乱的心跳逻辑（接受方无条件发送 `HeartbeatAck` 的线程）
   - _需求：1.2、1.3、2.1_

- [ ] 3. 实现双向应用层心跳模块
   - 连接建立后双方各启动独立心跳发送线程，每 5 秒发送 `KvmFrame::Heartbeat`
   - 收到 `Heartbeat` 时立即回复 `KvmFrame::HeartbeatAck`，收到 `HeartbeatAck` 时更新 `last_heartbeat_ack` 时间戳
   - 启动心跳超时检测：连续 15 秒（3 次）未收到 `HeartbeatAck` 则判定断线，通知重连逻辑
   - 将 TCP 读超时设置为 20 秒，避免读超时早于心跳超时触发
   - _需求：2.1、2.2、2.3、2.5、2.6、2.7_

- [ ] 4. 实现无限自动重连逻辑
   - 移除 `connection/manager.rs` 中的 `MAX_RETRIES = 5` 限制
   - 断线后进入无限重连循环：等待 3 秒 → 尝试连接 → 失败则继续循环
   - 重连成功后立即重启心跳线程（任务 3）
   - 提供 `stop_reconnect()` 接口供手动断开时调用，停止重连循环
   - _需求：3.1、3.2、3.3、3.4、3.6_

- [ ] 5. 在 TCP 连接建立时启用 Keep-Alive 系统保活
   - 在 `TcpStream` 建立后调用系统接口启用 `SO_KEEPALIVE`
   - 设置探测间隔 30 秒、探测次数 3 次、探测超时 10 秒（Windows/macOS 分别适配）
   - _需求：4.1、4.2、4.3_

- [ ] 6. 更新前端 UI：移除主控/被控文案，添加连接状态显示
   - 移除前端中"主控端"/"被控端"相关文案，改为中性描述（如"本机"/"对端"）
   - 添加连接状态展示区域：显示"已连接（对端 IP）"/"断开"/"正在重连...（第 N 次）"
   - 添加"断开连接"按钮（已连接时显示）和"重新连接"按钮（断开/重连中时显示）
   - _需求：1.7、5.1、5.3、6.1、6.2_

- [ ] 7. 实现前端断开/重连事件通知与手动操作
   - 后端通过 Tauri 事件向前端推送连接状态变更：`connected` / `disconnected` / `reconnecting(n)` / `reconnect_success`
   - 前端监听事件，断线时弹出 Toast"连接已断开"，重连成功时弹出"重连成功"
   - 重连失败超过 10 次时显示"重连失败，仍在后台尝试"提示
   - "断开连接"按钮调用后端 `disconnect` 命令，停止自动重连；"重新连接"按钮调用 `reconnect` 命令，使用上次 IP 立即发起连接
   - _需求：5.2、5.4、5.5、5.6、5.7、6.3、6.4、6.5_
