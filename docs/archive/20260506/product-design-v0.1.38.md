# KVMini v0.1.38 产品设计

> 版本：0.1.38 · 构建日期：2026-05-06 · 类型：可用性紧急修复 + 真 KVM 行为重做

## 1. 设计目标

修复 v0.1.37 上线后用户连续反馈的三个核心可用性缺陷，把 KVMini 从"看起来能用"升级为"真的能用"：

| 缺陷 | v0.1.37 表现 | v0.1.38 期望 |
|------|--------------|--------------|
| 扫描到设备点「连接」没反应 | 控制台报 `connect_to_device not found` | 一键连接成功，三条路径（discover/manual/history）行为一致 |
| 端口默认值混乱 | 监听端口/手动端口默认 8889，但真源 `KvmConfig::default().tcp_port = 23456` | 启动从 `get_settings` 拉取真源，所有 UI 默认值统一；保存后立即反映 |
| 共享后两台电脑同时响应 | 本地光标 + 远端光标都在动，等于"键鼠广播"而非 KVM | 软 KVM：本机控制本机时本机独占；切到对端时本机输入 100% 屏蔽 |

## 2. 设计原则

1. **第一性原理**：不假设、不修补，直接重做 KVM 控制流。把"键鼠输入到底由谁消费"作为根问题，从 `CGEventTap` 回调返回值这个最底层语义切入。
2. **奥卡姆剃刀**：默认值唯一真源（kvm-core），UI 不持有副本；删除而不是重写散落的字面量。
3. **爆炸半径可控**：`CGEventTapOptions::Default` 是高风险改动，必须保证 IDLE 状态 100% 放行，否则用户会完全无法操作电脑。
4. **TDD 守门**：每个修复点先写失败测试再实现。

## 3. 用户故事

### S1：扫描后一键连接（BUG-020）

> 作为用户，我打开 KVMini，点「扫描设备」，看到局域网里另一台设备，点「连接」按钮，应当看到状态从 `未连接` 变为 `已连接`，并能立即开始共享。

### S2：默认端口跟随设置（BUG-021）

> 作为用户，我在设置里把监听端口改成 19999，保存关闭。下次打开「手动连接」对话框，端口框默认应当显示 19999，而不是 8889 或 23456。

### S3：真 KVM 边界切换（BUG-022）

> 作为主控端用户，按下「开始共享」后：
> - 鼠标在本机屏幕内移动 → 只控制本机；
> - 鼠标移到布局右边缘（对端在右） → 自动切到控制对端，本机光标消失；
> - 鼠标在对端屏幕里移到对端的左边缘 → 自动回切本机；
> - 切换瞬间不会出现两台电脑光标同时移动的"双控"状态。

## 5. 验收标准（Acceptance Criteria）

| AC | 验证方式 |
|----|----------|
| 扫描到设备点连接成功率 100% | discover-devices.test.ts + connect-command.test.ts 全绿 |
| 任何 UI 端口默认值与 `kvm-core::config::KvmConfig::default().tcp_port` 一致 | port-defaults.test.ts |
| IDLE 时本机键鼠输入完全不受影响 | input_capture::tests::test_idle_state_passes_event_through + 手工：未点共享时打字、移动鼠标、滚轮均正常 |
| LocalControlling 时本机键鼠 100% 被吞 | input_capture::tests::test_local_controlling_swallows_event + 手工：开始共享后本机鼠标"卡住" |
| 鼠标触达布局边缘自动切控制权 | sharing.rs::tests::test_edge_detect_triggers_switch_to_local + 手工：左/右/上/下四方向各一次 |
| 设置页边缘触发开关持久化 + 立即生效 | kvm-edge-switch.test.ts 设置页分区子集 + 手工：关闭后仅快捷键能切，开启后边缘也能切 |

## 6. 非目标（明确不在本版范围）

- TLS 应用层加密（仅 v0.1.38 协商位，真加密留 v0.1.39）
- USB 链路（仍走网络）
- 多对端拓扑（仍 1:1）
- 鼠标光标本地隐藏（HideCursor/ShowCursor 当前为日志桩）
